== How it was checked

* Contrast: the palette is data in `html.zig` (`tones`); the CSS is written
  from it; `zig build test` computes the WCAG ratio of every text pair and
  every meaningful mark, light and dark, and fails below 4.5 (text) or 3
  (marks). Measured: worst text 5.34:1, worst mark 4.44:1.
* Rendered page: Chromium (preinstalled) at 1280x900 and 360x740, light and
  dark, on `full` and `hostile` fixtures. Per run: computed colour of every
  text node against its effective background, heading levels, horizontal
  overflow, script elements, `on*` attributes. Worst rendered text contrast
  6.23:1 (light), 6.63:1 (dark). That probe is an ad hoc script, not
  committed (the repo forbids Node); the contrast check above is.

== Findings that are not fixed

. *Meta refresh (WCAG 2.2.1 Timing Adjustable; technique F41).* TIERS.adoc
  requires the watched page to carry a meta refresh, and it does (10 s,
  `--watch` only; the one-shot page has none). A page that reloads itself
  can disturb screen-reader and magnifier users and cannot be paused. This
  is a conflict between the brief and the baseline, not a bug. Owner decision (2026-11-18): the interval is configurable, `--refresh N`,
  default 10 s, `0` omits the meta. The default still reloads, so a
  WCAG-clean deployment must pass `--refresh 0`.
. *Not tested:* a real screen reader, forced-colors / high-contrast mode,
  200 % and 400 % zoom (360 px width was tested), keyboard use beyond the
  one native `<details>` control.
. *Bidi controls* in job text are shown as U+FFFD rather than honoured. That
  is a safety choice, and it changes what a title with a deliberate RTL
  override displays.
